# GLOSSARY

## Home Assistant
The home automation platform application that runs as a Docker container on the Pi. Provides a web UI (port 8123), integrations for smart home devices, and automation rules.

## Pi (Raspberry Pi 4)
The host machine running Raspberry Pi OS with 8 GB RAM and an external SSD mounted at `/mnt/ssd`. Runs multiple containers (not dedicated to Home Assistant).

## Container (Docker Container)
An isolated process running Home Assistant, managed by Docker. Runs as the unprivileged `homeassistant` user. Persists state to a named volume.

## Named Volume
Docker's abstraction for persistent storage. Bound via bind mount to `/mnt/ssd/homeassistant` for HA's configuration, database, and logs.

## Unprivileged User (`homeassistant`)
A dedicated Linux user created by Ansible that runs the Home Assistant container. Owns `/mnt/ssd/homeassistant`. Provides security isolation.

## Playbook
An Ansible playbook that automates HA setup from your laptop via SSH to the Pi. Idempotent—safe to run multiple times. Contains roles, templates, and tasks.

## Role (Ansible)
A reusable unit of automation. The `homeassistant` role contains all tasks for setting up HA (install docker, create user, render compose file, start container, verify health).

## Compose File (docker-compose.yml)
Defines the HA service: image version, named volume mounts, port mappings, healthcheck, and environment. Generated by templating `docker-compose.yml.j2` with Ansible.

## Template (docker-compose.yml.j2)
A Jinja2 template version of the Compose file. Contains placeholders for version, paths, and other variables filled by Ansible at runtime.

## Configuration (configuration.yaml)
Home Assistant's core config file. Lives in the named volume. Defines integrations, automations, and device settings. Exported to git for backups and version control.

## Bare Minimum Setup
Initial HA installation with no integrations or automations pre-configured. Users add integrations manually after first boot via the web UI.

## Idempotent
An operation that produces the same result regardless of how many times it runs. The Ansible playbook is idempotent—running it twice is safe (skips if container exists).

## Upgrade Task
A separate Ansible task that updates HA to a new version: stops the old container, pulls the new image, starts the new container. Downtime ~10-30 seconds.

## Health Check
A Docker health check configured in Compose that periodically verifies HA is responding. Used by Ansible to confirm readiness after startup.

## Bind Mount
A Docker volume driver that directly mounts a host directory (e.g., `/mnt/ssd/homeassistant`) into the container. Simpler than named volumes but less portable.
