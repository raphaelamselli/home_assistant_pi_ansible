# Home Assistant on Raspberry Pi (Docker)

Automated setup of Home Assistant running in Docker on a Raspberry Pi 4, coexisting with other containerized services on the same host.

## Why This Approach?

- **Non-invasive**: Runs Home Assistant in Docker, not as Home Assistant OS. Your Pi can host other services simultaneously.
- **Reproducible**: Ansible playbook handles all setup—idempotent and repeatable across multiple Pis.
- **Explicit upgrades**: Pinned Home Assistant versions prevent surprise breaking changes. Upgrades are intentional.
- **Secure**: Container runs as an unprivileged user, isolated from root and other services.
- **Persistent**: Configuration lives on external SSD for longevity and easy backups.

## Prerequisites

- **Raspberry Pi 4** (8 GB RAM recommended) running [Raspberry Pi OS](https://www.raspberrypi.org/software/)
- **External SSD** mounted and available (e.g., at `/mnt/ssd`)
- **Docker + Docker Compose** installed on the Pi ([installation guide](https://docs.docker.com/engine/install/raspberry-pi-os/))
- **SSH access** from your laptop to the Pi
- **Ansible** installed on your laptop ([installation guide](https://docs.ansible.com/ansible/latest/installation_guide/intro_installation.html))

## Quick Start

### 1. Clone or Download This Repository

```bash
git clone <repo-url> home-assistant
cd home-assistant
```

### 2. Configure Your Environment

Copy `.env.example` to `.env` and edit as needed:

```bash
cp .env.example .env
# Edit .env with your preferred HA version and SSD path
```

### 3. Set Up Ansible Inventory

Create an `ansible/inventory.ini` file:

```ini
[homeassistant]
pi_host ansible_host=<pi-ip-or-hostname> ansible_user=pi
```

Replace `<pi-ip-or-hostname>` with your Pi's IP address or hostname (e.g., `192.168.1.100` or `raspberry-pi.local`).

### 4. Run the Playbook

```bash
cd ansible
ansible-playbook -i inventory.ini playbook.yml
```

Ansible will:
- Verify Python 3, Docker, and Docker Compose
- Create the `homeassistant` unprivileged user
- Set up directories on your SSD
- Render and deploy the Docker Compose file
- Start the Home Assistant container
- Wait for it to be ready

### 5. First-Time Setup

Once the playbook completes:

1. Open your browser to `http://<pi-ip>:8123`
2. Create your admin user
3. Add integrations via **Settings > Devices & Services**
4. Create automations via **Settings > Automations**

## Upgrading Home Assistant

To upgrade to a new version:

1. Update `HA_VERSION` in `.env`
2. Run the playbook again:

```bash
ansible-playbook -i inventory.ini playbook.yml
```

The playbook will pull the new image and restart the container (brief downtime, ~10-30 seconds).

## Configuration & Backups

Home Assistant configuration lives in `/mnt/ssd/homeassistant/`. You can:

- **Inspect config**: SSH into the Pi and browse `/mnt/ssd/homeassistant/`
- **Version control**: Export `configuration.yaml` to git for changes you want to track
- **Backup data**: Snapshot `/mnt/ssd/homeassistant/` before major upgrades
- **Export/Restore**: Use Home Assistant's built-in backup feature via the web UI

## Logs

Container logs are available via:

```bash
docker logs homeassistant
```

Persistent logs also live at `/mnt/ssd/logs/` (rotated, max 30 MB).

## FAQ

**Q: Can I run Home Assistant on a Pi Zero or Pi 3?**  
A: Theoretically yes, but Pi 4 (8 GB) is recommended. Earlier models will be slow.

**Q: Can I use a USB stick instead of an SSD?**  
A: Yes, as long as it's mounted somewhere on the filesystem. Update `SSD_PATH` in `.env`.

**Q: What if I already have services running on port 8123?**  
A: Update `HA_PORT` in `.env` to a different port. The playbook will error if the port is in use.

**Q: How do I back up my Home Assistant setup?**  
A: Snapshot `/mnt/ssd/homeassistant/`. You can also use Home Assistant's built-in backup feature.

**Q: Can I run multiple Home Assistant instances on the same Pi?**  
A: Yes, if you use different ports and separate data directories. Duplicate the role in the playbook.
